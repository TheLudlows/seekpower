# anyseek / Meilisearch：小规模中文全文检索诊断

2026-10-24，本地实验；生产代码固定 `6d28798a300bb947b2eb1d3e48e928d193103e17`，Meilisearch Community `v1.55.0`。没有修改生产代码、资源预算或容量上限，没有推送。

## 结果与适用范围

目前不能宣称完成了“相同检索语义、5000条”的性能比较。完整执行的是双方默认搜索行为的 **1000条** 对照、Meilisearch restricted 诊断、双方功能探针、进程重开和默认配置下的写入并发实验。anyseek 的两个容量拒绝均保留，未重试提高预算，也未分摊到多个 collection。

## 容量与并发发现

- anyseek `UnicodeAlphanumericZH` 的1000条预检接受 **384** 条，第385条 `storage_error / resource budget exhausted`，同批其余项 `not_attempted`。未进入质量/计时阶段，未把部分装载当作1000条。调用点仍需独立定位：拒绝正好位于128次更新轮换边界；源码每个中文分析器持有约64MiB的后台预算，而同subject后台上限384MiB，轮换会同时保留旧视图和候选视图。这是有代码依据的解释线索，日志未证明具体失败的 reserve 调用。
- 默认分词的5000条预检接受 **2176** 条，第2177条 `record build resource budget exceeded`。该独立逻辑构建预算单次上限256MiB，不等于RSS或原文大小。此点也在128更新轮换边界，且分段累计/全量重建具有不同瞬时预算。未运行5000条性能比较，也未运行Meilisearch5000条以制造不对称排名。
- 默认配置并发8的三轮中，anyseek有53,620次HTTP429及21,212次客户端传输错误（状态0）；原始错误文本在JSONL中。429是正式准入拒绝；其前台同subject并发上限4。连接错误还包括拒绝后复用连接时的 Broken pipe 等，不能全部算成服务端执行失败。客户端没有退避，闭环快速拒绝会放大拒绝请求占比；这是指定负载策略的结果，不代表业务流量固定失败率。
- 原文仅约0.45/1.96MB不足以判断1000/5000可装载，规范快照预算也不是唯一瓶颈。本轮实际结果纠正了仅根据记录数和原文字节估算可用规模的假设。

## 写入期间查询与持久化

中文配置无法装载，明确改用双方 **default**、全新数据根各装1000条。固定2次更新/秒，共100个既有ID，四个查询客户端持续50秒。成功/失败逐条保存，不重试写入，也不把拒绝吞成成功。

|---|---:|---:|
|更新成功确认|35/100|100/100|
|独立重开后实际更新|35/100|100/100|
|未确认但实际已更新|0|0|
|查询成功QPS|689.1|1242.3|
|查询错误率|10.16%|0%|

anyseek四个查询与额外写入竞争同subject准入，失败不是达到10000操作账本限额。实际持久化内容通过双方正式GET文档接口逐条核对，未确认写入没有假定为未执行。这里采用有限单次写入突发；无队列/退避策略比较。

anyseek每次应用确认要求 durable+visible；Meilisearch提交返回202后等待对应task成功，再检查数量。各批均50条，构建耗时包含这些不同确认协议及轮询。anyseek另计checkpoint约582ms；Meilisearch没有请求对应checkpoint，其零耗时字段是脚本占位，**不能用作checkpoint性能比较**。首次启动到健康约54/53ms，进程重开约103/52ms；重开首轮逐查询数据另存。这些是一次测量，OS页缓存未清除，不是真正冷缓存或断电持久性验证。

## 数据、语义与测量边界

- 原始MIRACL中文10个压缩分片全部校验SHA256和记录数，共4,934,368条。固定seed，从393个官方dev查询选40个；纳入其全部397个已判定文档（含91个不同相关文档），再从全语料按文档ID哈希补干扰文档。1000/5000嵌套，所选查询相关文档覆盖100%。这是相关文档富集的小语料诊断，**不是完整MIRACL成绩**；未判定文档在指标中按不相关处理。
- 保留原始title/text，双方增加相同稳定ID及确定性日期字段；三份代表原文通过正式GET逐字段核验。另10个中文标题片段+原文英文词构造查询没有人工相关性标注，不混入质量指标；1000/5000中含Latin文本的记录分别264/1413，不是独立英文基准。
- 探针分别记录AND、限定字段、过滤、前缀、错字、繁简。关闭Meilisearch前缀/错字后对应探针不再命中，但它仍在“中国/中國”间匹配，anyseek探针只匹配同字形（text_normalization=None，不能据此推断其他规范化设置的能力）。双方排名次序不同；不称 restricted 为完全共同语义。
- 同一AMD EPYC9V74 KVM容器，5个可见CPU，cgroup 4CPU quota/16GiB；服务依次运行，均固定CPU0–1，客户端CPU2–3。无专用宿主或独立硬RAM限制；Meilisearch索引线程2，双方Tokio/Rayon环境2，内部内存策略仍不同。
- 热查询预热两遍，随后并发1/4/8各3轮、每轮5秒；HTTP客户端连接复用、包含JSON解析，状态0为传输失败；成功延迟单列，错误率全量计算。有限closed-loop测试存在协调遗漏及客户端瓶颈可能，不代表极限吞吐或长时尾延迟。未随机化服务顺序，无性能置信区间。构建/重开/写混合各一次。
- RSS/HWM采样100ms，为服务主进程所有阶段峰值；磁盘包括各自数据根及原文、索引、账本/日志，另存逻辑/分配字节。不同持久化架构和overlay稀疏文件使磁盘数不能直接解释为索引压缩率。

## 复核与下一步

脚本与协议见 [README.md](README.md)、[PROTOCOL.md](PROTOCOL.md)，原始证据位于仓库 `artifacts/benchmark/`（本地忽略目录，未上传）：`environment.json`、`data/selection-manifest.json`、`summary.json`、`raw/<实验>/run.json`、每请求JSONL、完整质量响应、资源采样和更新核验。`raw/sequence.json`记录5000失败后停止后续步骤。失败实验保留已接受数量、拒绝响应和数据根。

建议顺序（未实施）：
1. 核准中文自然问句的产品搜索契约及推荐查询方式；保留当前AND语义，另行讨论是否提供可选词项退让。没有这一步，速度排名没有可比质量基础。
2. 独立定位中文轮换的分析器预算重复保留与默认分词全量构建预算，补真实HTTP语料回归；先证明所有权和峰值，再决定实现方案，不能直接加大上限。
3. 定义拒绝/退避与目标并发，稳定完成同规模、同查询意图且有命中的质量评测后，再重跑吞吐和写入共存。
4. 5000及更大规模、更多查询、英文独立标注、长时统计和真正冷缓存留待上述核心问题解决。10万、向量/混合、真实S3/系统断电不在本轮验收内。

## 实验复核补充（2026-10-24）

### 精确配置和可比性

anyseek包版本3.4.1，生产提交6d28798a300bb947b2eb1d3e48e928d193103e17，release/locked/server构建。默认API省略tokenizer，按api_types.rs解析为UnicodeAlphanumeric；中文restricted显式UnicodeAlphanumericZH。operator默认and→QueryType::Intersection；or→QueryType::Union。正式服务采用Bm25fProximity、ngram_indexing=9、frequent_words=English、字段boost=1、Shared字段长度规范化、text_normalization=None。Top10，offset0，count=false，无过滤/排序，搜索title和text，返回id/docid/title/text；没有向量。具体请求构造在run.py，服务端配置返回在settings.json。

Meilisearch Community v1.55.0，官方linux-amd64 SHA256 7e33f5889235f14290074a19a6d3574bd9b10fb2ee8731eabb7dafd0714b0513。默认请求省略matchingStrategy，使用last；typoTolerance.enabled=true（oneTypo=5,twoTypos=9），prefixSearch=indexingTime。restricted为matchingStrategy=all、typoTolerance.enabled=false、prefixSearch=disabled，其余配置保持。searchableAttributes顺序title,text；默认rankingRules为words,typo,proximity,attributeRank,sort,wordPosition,exactness，stopWords/dictionary/synonyms为空，localizedAttributes=null，maxTotalHits=1000。last是从尾部逐步放弃词项，**不是anyseek OR的同义实现**。[官方matchingStrategy说明](https://www.meilisearch.com/docs/capabilities/full_text_search/how_to/use_matching_strategy)。

**没有建立可用于引擎优劣排名的同语义、同质量子集。** 三文档正例复核和英文/字段/过滤探针只验证行为，不构成官方质量分数或负载性能集。原RESULTS里的QPS/质量数值是特定配置的真实观测，作为等语义引擎比较无效；不强行归一、挑查询或给胜负排名。Meilisearch未暴露本次使用的词项明细，不能用anyseek分词结果代替它。
